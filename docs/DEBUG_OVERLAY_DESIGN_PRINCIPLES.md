# 调试悬浮窗 · 设计理念

> 这份文档是界面实现**之前**的事实来源。界面只是它的投影：先改这里，再改界面。
> 配套材料：`调试悬浮窗-接线清单.md`（能调什么）、`docs/DEBUG_FLOATING_WINDOW_DESIGN.md`（为什么这么立项）。
> 本文管的是：**做成什么样、为什么这么分、每句话怎么写**。

---

## 0. 一句话定位

调试悬浮窗是给**公测玩家**用的「自助检修台」：面向懂魔纪、不懂技术的人，
让他们**不用找人问**就能完成三件事——**修复下载、送出日志、自己动手拨开关**。
每个开关的用途、使用时机、后果必须写在界面上本身——
「去问问开发者」不是设计，是设计的失败。

它不是开发者工具的图形化，不是 34 个开关的表格皮肤。开关表只是它功能的一部分。

---

## 1. 用户画像与到访场景

**用户**：魔纪公测玩家。知道什么是序章、热更、资源包；不知道什么是钩子、注入、ABI、fail-open。
对「开关」的心理模型是电灯开关：开了就该立刻有用——所以「改完要重启」必须反复说。

**三种到访场景**，决定了信息架构：

| 场景 | 玩家状态 | 界面要给的 |
|---|---|---|
| ① 看了公告/群里的排查教程而来 | 「公告说打开某某开关」 | 按名字能找到、按分类能逛到，每行写清这是干嘛的 |
| ② 出问题病急乱投医 | 下载卡死/进不去游戏，自己摸进来的 | 首页直接给「资源修复」「进入游戏」两个出口，别让他先看到 34 个开关 |
| ③ 好奇点开 | 没目的，随便看看 | 明确告诉他「平时不用动这里」，并保证他乱点也出不了事（勾选不落盘、危险项折叠） |

场景③是最大量的沉默用户。设计按「一个完全不想看说明的人会怎么乱点」来兜底。

## 2. 六条设计原则

以下每条都有对应的界面裁决，后文所有具体设计都能追溯到其中一条。

### P1 · 先回答「我该不该在这」，再给按钮
每个功能页顶部固定一张「什么时候用这里？」卡片，用玩家语言列场景
（「下载一直卡住不动」「提示校验失败」），通过场景自检，而不是让玩家理解功能。

### P2 · 说人话，信息分三层
任何开关/资源的展示都分三层，逐层变浅：
1. **接口名**（如 `noTtfHooks`）——给公告、截图与真机互相对照用，等宽感、缩小；
2. **官方说明**（来自接线层 `COL_DESC`）——准确但偏技术；
3. **白话说明**（本设计定义，见 §5）——像什么、什么时候用、用了会怎样。
玩家只看第三层也能正确操作；开发者用第一层精确定位。

### P3 · 状态说结论，不让人解读原始数据
首页状态卡只说「一切正常 / 有 N 个改动待重启 / 有 N 个资源包在处理」。
资源页每行给四态结论（等待/下载中/完成/出错）而不是字节数。
原始数据（速度、百分比）可以有，但永远不作主信息。

### P4 · 改动永远可后悔、可解释
- 勾选只改内存，点「应用并重启」才落盘（接线层 `applyAndRestart` 的语义，界面不加即时生效的捷径）；
- 「待重启」三级露出：顶部 HUD 小字 → 开关总览提醒条 → 行内角标，玩家在任何一个层级都不会误以为「开关坏了」；
- 每个列表页都有「全部关闭」出口——开关全关 = 和没装小助手一模一样，这句话直接写在页面上。

### P5 · 危险的东西要绕两道弯
- 「排查开关」在首页就标「进阶」，副标题写「每个开关都写清了用途和后果，看懂再动」；
- 进入开关区先过一道琥珀色警告横幅（「这些开关用来排查问题，不是加速器」）；
- 故障演习类（§4 的 F 类）默认折叠，展开要再点一次确认，行内红色标注「会让功能看起来坏掉」。
  ——这是 README 里「玩家自己开了降级模式却不知道，然后来报游戏坏了」这一支持成本的正面解法。

### P6 · 界面只是接线层的投影
开关名单、状态、行数全部来自 `CNDebugBridge.flagTable()`，界面不抄副本。
白话建议做成**按开关名索引的注释表**（§5），查不到就降级为只显示官方说明——
native 加了新开关，界面最坏情况是「少一句建议」，绝不会「没有这一项」。

### P7 · 不给玩家「断同步」的开关
客户端版本号烧录在 native（`CLIENT_VERSION`）里，**APK 外观完全一样**——
玩家一旦切断服务器→客户端的下发通道，没有任何外部信号能发现他已掉队，
图标、版本号全都正常，只是我们再也推不动他。因此：

> 凡效果是「让远端配置/更新对这台客户端失效」的开关，**一律不进面板**，
> 不论它在 flagTable 里是否存在。

当前命中的三个：`skipVersionCheck`（版本检查）、`skipHotUpdate`（热更）、
`skipMirrorConfig`（线路配置 config.json——换线、proxy 模式、force_aria2 都走它）。
开关本体保留在 `CNDebugFlags` 供维护者 su 手动排障（面板出现前玩家本就碰不到私有目录），
维护者手动打开时 HUD 照常显示——开发者看截图依然能发现。

### P8 · 入口可再开，轮子不再造
悬浮窗与下载浮层功能有重叠时：**触发入口可以写第二份，动作逻辑和状态永远只有一份**。
悬浮窗的角色是「转一道手」和「只读投影」，不是平行实现。
仓库已有先例：`CNDownloadUiAssist` 的让位协议——悬浮窗挂上后浮层撤掉自己的
「停留」「重下」按钮，但动作逻辑一行没动，只是按钮挪了窝。
造两份轮子的代价不是代码量，是**两份状态迟早不一致**，而玩家只会得出
「这个功能坏了」这一个错误结论。重叠清单与各自的唯一事实来源见 §8。

## 3. 信息架构（页面树）

```
悬浮小球（常驻，可拖动贴边，闲置半透明）
└─ 首页「调试小助手」
   │  状态卡（结论式）＋ 四个入口
   │
   ├─ 资源修复 ………… 场景②主出口。15 资源包列表 + 重下 + 进度
   ├─ 进入游戏 ………… 场景②副出口。大状态 + 大按钮 + 停留开关
   ├─ 排查开关（进阶）
   │   ├─ 分类总览 … 警告横幅 + 待重启提醒条 + 六个分类入口（§4）
   │   └─ 分类子页 … 该类开关列表（三层信息）+ 底部「全部关闭 / 应用并重启」
   └─ 日志与求助 …… 三步指引 + 日志预览 + 打包分享
首次挂载未完成授权时：权限引导页（替代以上一切）
```

页面职责一句话：
- **首页**：告诉你现在正不正常，然后把你分流到该去的地方。
- **资源修复**：某个包坏了，单独重下它——不需要懂是哪个，列表会说话（出错的行自己是红的）。
- **进入游戏**：把「停留」这个技术概念翻译成一个大按钮和一句「放心点」。
- **分类总览**：让排查公告能写「进第三行那个分类」而不是「往下翻找某某英文」，玩家自己逛也能逛到。
- **分类子页**：拨开关的地方，也是「待重启」语义的主战场。
- **日志与求助**：把「发日志」写成三步教程，顺便教会玩家截图带 HUD。
- **权限引导**：手把手过一次系统授权，给「暂不开启」出口。

## 4. 开关分类体系（核心）

### 4.1 分类维度：作用对象

不按实现侧（Java/native）、不按字母序，按**「这个开关动的是游戏的哪部分」**分。
理由：玩家的语言是作用对象（「下载」「汉化」「序章」），
没人说「把 native 层第三个开关打开」。实现侧归属（Java/native）缩小为分类页副标题里的一行字。

### 4.2 六个分类

按「玩家自助排查时的使用频率」排序：

| # | 分类 | 数量 | 一句话定位 | 典型场景 | 风险 |
|---|---|---|---|---|---|
| A | 启动与更新 | 5 | 管「进游戏之前那一串流程」 | 卡在启动页/下载页 | 中 |
| B | 下载与网络 | 8 | 管「资源从哪条线、怎么下」 | 下载慢/失败/连不上 | 低 |
| C | 汉化与文本 | 6 | 管「游戏里的中文显示和缺漏记录」 | 字体方块、反馈没翻的句子 | 低（两个记录类无害） |
| D | 教程与序章 | 9 | 管「序章播不播、从哪段播」 | 测序章、快速过教程 | 低 |
| E | 声音与引擎 | 1 | 管「引擎的声音参数」 | 破音/变调排查 | 低 |
| F | 故障演习 · 仅供开发 | 5 | **故意**让某环节坏掉，验证兜底（像消防演习的假警报） | 开发自测 | **高：开了就像游戏坏了** |

Java / native 两侧来源在分类页副标题标注，如「含引擎层 4 项」，不作为分类依据。

> 数量是**面板可见的底层开关**数：两侧目录合计 38 个（`CNDebugFlags.KNOWN` 21 +
> `MagiaLegacy.cpp kDebugFlags` 17），其中 4 个有意不进面板
> （`skipVersionCheck` / `skipHotUpdate` / `skipMirrorConfig` 是 P7 剔除的断同步开关，
> `skipBootWatchdog` 是后加的逃生开关），面板可见 **34** 个。
> 经 §4.5 合并后（C 类 6 开关 → 5 个控件、D 类 9 开关 → 4 个控件），
> 全表面板呈现 **28 个控件**。玩家看到的是控件，不是开关表。
>
> ⚠ 上面这些数字曾长期漂着（本文写 34/31/25、`KNOWN` 15、`kDebugFlags` 19，
> 而代码里分别是 38/34/28、21、17）。现已由
> `tools/check-debug-flag-catalog.py` 逐个钉住——**改开关表必然会让这里红灯**，
> 所以不必再靠人记得回来改。

### 4.3 完整归属表（真实名单）

> 名单以 `CNDebugFlags.KNOWN`（21）与 `MagiaLegacy.cpp kDebugFlags`（17）为准。
> 「白话建议」列即 §5 注释表的内容来源。
>
> ⚠ **本节的明细行不全**：B 类代码里是 8 项，下面只列了 4 项，缺
> `useSingleThread` / `useWebviewDebug` / `logWebviewRequests` / `countWebSocket`
> 四条的白话说明（它们在面板上是可见的，文案见 `CNDebugOverlay` 的注释表）。
> 这是历史遗留的漏写，不是「有意不列」。守卫只核对数字，不会替人写文案——
> 补文案得有人真去理解那四个开关对玩家意味着什么。

#### A. 启动与更新（5）
| 开关 | 官方说明（接线层） | 白话说明 |
|---|---|---|
| skipInstaller | 不跑首次安装（资源缺失时会停在浮层） | 相当于**跳过装机直接开机**：用来对照排查「是不是安装环节出的问题」；资源不齐时会停在下载页 |
| skipOverlay | 不显示浮层（连带不下发引擎闸门标记） | 只是**捂上下载的仪表盘**：下载照跑，只是你看不见。排查浮层显示问题时用；别慌，它没在偷懒 |
| skipRestart | 装完/序章后不自动重启 | 装完资源本要**关门重开一次**才算数；这个开关让它不重开。排查「装完重启失败」时用 |
| skipSlowAsk | 网络慢时不弹询问框，静默处理 | 网慢时游戏会问「还等吗」，开了它就**不问了自己拿主意**。嫌烦可以开，基本无害 |
| noOverlayGate ⚙ | 浮层期间不闸住引擎（引擎照常推进） | 下载时引擎本来被**按住暂停**；这个开关=松手。排查「卡在下载页」时用；开着可能游戏进去了资源还没下完，画面会变奇怪 |

> 本类原含 `skipVersionCheck`、`skipHotUpdate`，已按 P7 移出面板（断同步通道）。

#### B. 下载与网络（8，本节只列出 4 条，见 §4.3 开头的说明）
| 开关 | 官方说明 | 白话说明 |
|---|---|---|
| useAria2 | 资源下载改用备用引擎（默认关） | **备用下载器**：主水管怎么修都不出水时，换墙上另一根消防管。下载反复失败时打开试试——它走独立通道，主引擎的毛病影响不到它 |
| skipWebProxy | 不装 WebView 拦截层代理，一律透传直连 | 游戏内网页本有个**前台接待**帮忙中转；这个开关=跳过前台自己直连。网页打不开时，用来判断是不是中转环节的问题 |
| noHttp2Bump ⚙ | HTTP/2 并发数保持引擎原本的 4 | 我们把下载**同时干活的人数**从 4 提到 10；这个开关退回 4 人。人多反而互相挤（下载变更慢）时开着试试 |
| tlsProbe | 跑一次 TLS 探针（本机自签名端点 + 引擎自带 OpenSSL） | **开发用**：让游戏在本机自己跟自己做一次加密握手，验证「以后能不能连我们自己的服务器」。跑完就停，不改变任何游戏行为；结果在日志里 |

> 本类原含 `skipMirrorConfig`，已按 P7 移出面板（断同步通道）。

#### C. 汉化与文本（6）
| 开关 | 官方说明 | 白话说明 |
|---|---|---|
| logI18nMiss ⚙ | 记录未命中翻译表的含假名串（去重） | **帮你随手记下路上看到的「没翻译的招牌」**：想反馈缺漏就打开它，去游戏里逛一圈，再从「日志与求助」发出来 |
| logI18nMissAll ⚙ | 同上但不筛内容（噪音大） | 上面那项抓不到你想找的句子时再用——它连英文数字都记，**日志里九成是废话** |
| noI18nLabel ⚙ | initLabel 不替换文案（引擎侧标签回日文） | 汉化像坐在引擎旁的**翻译官**；这个开关让他对「启动标签」下班。开了启动页变回日文——用来对照「这句汉化是不是我们加的」 |
| noI18nSetString ⚙ | setString 系不替换文案 | 同上，但管**游戏内大段文本**；开了大片文本回日文 |
| noInitLabelHook ⚙ | **不安装** initLabel 钩子（排除原型/ABI 问题） | 普通开关是「关掉改装件的功能」，这个是**把整套改装件从引擎上卸下来**——用来判断问题是不是改装件本身造成的。前面开关都试过没用再用它；卸掉后对应汉化全部回日文 |
| noTtfHooks ⚙ | **不安装** createWithTTF/setTTFConfig 三个钩子 | 同上，卸的是**字体那套**改装件 |

（⚙ = 引擎层/native 开关，分类页副标题注明数量即可，行内不必区分。）

> **logI18nMiss / logI18nMissAll 合并为一个单选控件**（规则见 §4.5-M2）：
>
> | 控件：翻译缺漏记录 | 写回的底层开关 |
> |---|---|
> | ○ 不记录（默认） | 两者都不写 |
> | ○ 只记没翻的句子（去重，推荐） | logI18nMiss |
> | ○ 记录全部，含英文数字（日志里九成是废话，上一项抓不到时再选） | logI18nMissAll |

#### D. 教程与序章（9）
| 开关 | 官方说明 | 白话说明 |
|---|---|---|
| skipTutorialPrompt | 不弹「是否播放序章」询问框 | 不再每次问「要不要看序章」。嫌烦可以开 |
| noTutorialForce ⚙ | 不强制序章（即使标记在，也照常进主页） | 标记要求重播序章时**装作没看见标记**。排查「一直被拉去看序章」时用 |
| noTutorialGuard ⚙ | 序章期间不起 WebView 看门狗 | 序章期间有个防卡死的**护航员**；这个开关让它休息。排查序章卡死时用——开着护航员不在，卡死风险自己担 |
| tutorialSkipToBattle1 ⚙ | 序章跳到第 1 场战斗前 | ┐ |
| tutorialSkipAfterBattle1 ⚙ | 序章跳到第 1 场战斗后 | │ |
| tutorialSkipToBattle2 ⚙ | 序章跳到第 2 场战斗前 | ├ **合并为一个单选控件**，见下 |
| tutorialSkipAfterBattle2 ⚙ | 序章跳到第 2 场战斗后 | │ |
| tutorialSkipToBattle3 ⚙ | 序章跳到 CONNECT 教学战前 | │ |
| tutorialSkipAfterBattle3 ⚙ | 序章跳到结尾剧情（收尾最快） | ┘ |

> **六个跳段开关合并为一个单选控件**（规则见 §4.5-M1），互斥从「文档约定」变成「控件保证」。
> 给玩家的一句话：**就像视频的章节跳转**——选从哪一段开始看序章。
>
> | 控件：序章从哪段开始 | 写回的底层开关 |
> |---|---|
> | ○ 从头完整播放（默认） | 六个都不写 |
> | ○ 第 1 场战斗前 | tutorialSkipToBattle1 |
> | ○ 第 1 场战斗后 | tutorialSkipAfterBattle1 |
> | ○ 第 2 场战斗前 | tutorialSkipToBattle2 |
> | ○ 第 2 场战斗后 | tutorialSkipAfterBattle2 |
> | ○ CONNECT 教学战前 | tutorialSkipToBattle3 |
> | ○ 直接到结尾剧情（最快） | tutorialSkipAfterBattle3 |
>
> 玩家再也不需要理解「同时开多个以最远为准」——控件里根本选不出两个。

#### F. 故障演习 · 仅供开发（5）—— 默认折叠
| 开关 | 官方说明 | 白话说明 |
|---|---|---|
| failConfigFetch | 【注入】config.json 一律拉取失败 | **消防演习用的假警报**：故意让配置拉取失败，看兜底系统动不动。开了对应功能一定失败，正常游玩别碰 |
| failVersionQuery | 【注入】版本 json 查询一律失败 | 同上，假装「查不到版本」 |
| slowVersionQuery | 【注入】版本查询拖慢（验慢网询问框） | 同上，假装「网特别卡」 |
| failDownload | 【注入】资源/热更下载一律失败 | 同上，假装「怎么下都失败」 |
| failHotupdateApply | 【注入】热更事务应用到一半失败（验回滚） | 同上，假装「更新装到一半出事」 |

### 4.4 新开关落位规则（给维护者）

新开关出现时按决策树归类，**不许新增第七个分类**（分类数是界面骨架）：
0. 会切断服务器下发通道（版本/热更/线路配置等）？→ **不进面板**（P7），维护者手动使用；
1. 是故意制造故障的？→ F；
2. 改的是「进游戏之前的流程链」？→ A；
3. 改的是资源下载或网络连接？→ B；
4. 改的是文本/字体显示，或记录翻译缺漏？→ C；
5. 改的是序章/教程流程？→ D；
6. 其余引擎行为改动 → E。

落进分类后再过 §4.5 的 M1/M2/M3，决定它以勾选、单选还是危险开关呈现。
注释表里没有该名字时，界面只显示官方说明（P6 降级），**不允许**因为没写白话建议就不显示该开关。

### 4.5 控件类型：不止是勾选框

开关的语义形状决定控件形状，不是一律给勾。三种控件：

| 控件 | 适用语义 | 用在哪 |
|---|---|---|
| **勾选开关**（默认） | 独立的布尔改动，开/关互不干扰 | A、B、E 类全部，C、D 类的独立项 |
| **单选控件**（点行展开选项列表，手风琴式） | 多个开关是**同一维度的互斥取值**，或存在覆盖关系 | D 类跳段（6→1）、C 类缺漏记录（2→1） |
| **危险开关**（红色 + 确认弹窗） | 开了会让功能「看起来坏掉」 | F 类全部 |

合并判定（给维护者，写新开关时过一遍）：
- **M1 互斥即合并**：几个开关同时开只有其一会生效（或语义上无意义）→ 单选控件。
  互斥从「文档约定」升级为「控件保证」——玩家根本选不出两个。
- **M2 覆盖即分级**：一个开关的效果完全包含另一个（All ⊃ Miss）→ 合并成程度递进的单选
  （不记录 / 只记缺漏 / 记录全部）。
- **M3 像坏即标红**：开了之后游戏某个环节必然失败 → 危险开关，确认弹窗文案必须说清「哪部分会坏」。

单选控件的读写规则（实现侧契约）：
- **读**：把磁盘上的开关集合映射回选项。正常情况 0 或 1 个文件，直接对应选项；
- **异常**：磁盘上同时存在多个（玩家用别的方式写过）→ 按引擎实际行为显示生效项
  （跳段=最远项），选项下挂一行琥珀小字「检测到多个跳段标记，实际按最远生效；在这里选一项即可修正」；
- **写**：选哪项就只写哪个开关的文件，同组其余不写（`applyAndRestart` 的全量语义天然保证清掉旧值）；
- **待重启**：整个控件一枚角标——「磁盘选项 ≠ 生效选项」时挂「待重启」，不进单个选项里。

## 5. 白话注释表（schema 与降级）

界面持有的一份**注释层**（不是开关表副本）：

```
name        →  plain:  一句话白话（可选，缺省用 COL_DESC）
               advice: 建议标签（可选）——枚举：
                        KEEP_OFF   建议保持关闭
                        LAST_RESORT 前面的开关都试过没用，再用它做最后对照
                        FEEDBACK   反馈问题时可以打开
                        HARMLESS   不喜欢默认行为就可以开
                        DEV_ONLY   仅供开发（F 类全部）
               risk:   改了会有什么可见后果（可选，琥珀色行）
```

规则：
- 键是开关名；**查不到 = 该开关照常显示**，只是没有第三行；
- 注释表里**多出来**的名字（开关已删）静默忽略，启动时可记一条日志；
- 状态永远以 `flagTable()` 为准——注释表永不参与状态判断。

## 6. 文案规范

**语气**：像一个懂游戏的朋友在群里教你，不像说明书，更不像编译器。

**句式模板**（写新文案时套用）：
- 场景指引：「什么时候用这里？· …… · ……」（动词开头，说玩家的处境，不说功能）
- 建议：「建议保持关闭」「想……可以打开它」「……时开着试试」
- 安抚：「放心点：……」「重启只是关掉重开，不会丢任何进度」
- 后果：「开着会……，用完记得关」

**复杂开关三段式 + 比喻**：难理解/作用复杂/副作用大的开关，白话说明按
「**像什么 → 什么时候用 → 用了会怎样**」写，比喻打头（例：`noTtfHooks`
=「我们给游戏换了副眼镜；这个开关=摘掉用原装的。字变方块时用」）。
比喻的选材来自玩家的生活经验（水管、仪表盘、前台接待、翻译官、消防演习），
不来自计算机概念。**写了比喻还不够人话，就是比喻没选好，换，不许加术语解释。**

**禁止推诿式文案**：界面任何角落不得出现「在开发者/客服指导下使用」「请咨询」
「按指引开启」这类把理解成本转嫁给人的写法。写不清什么时候用，是文案没写完，
不是玩家该去问。

**禁用词表**（界面文案一律翻译）：

| 禁用 | 替换为 |
|---|---|
| 钩子 / Hook | 「一套改动」「汉化功能」 |
| 注入 / fault injection | 「故意让它失败（开发测试用）」 |
| fail-open / 静默放行 | 「不弹窗，默默继续」 |
| 落盘 / 持久化 | 「保存」「记下来」 |
| native / 引擎层 | 「引擎层」（仅出现在副标题，不进正文） |
| applyAndRestart 等接口名 | 「应用并重启」 |
| ABI / 原型 / 采样率 | 不解释概念，只说后果：「字变方块时排查用」「破音时排查用」 |
| 客服 / 请按指引操作 / 咨询管理 | 把指引直接写在界面上；日志的归宿写「发给开发者」 |

**数字与状态**：能用结论就不用数字（P3）；必须出现数字时给单位和人话（「3.2 MB/s」可以，「3276 KB/s」不行）。

**开关名直出**：接口名保留原文不翻译——它是公告、截图与真机之间对得上的暗号，翻成中文反而对不上。

## 7. 状态与反馈模型

- **两列状态**：勾选框 = 磁盘（下次启动）；绿点 = 当前生效。两者不一致 → 琥珀「待重启」角标。
  两列永不合并成一个勾（接线清单红线，也是玩家「电灯开关」心智的正面冲突点，靠三级露出化解）。
- **待重启三级露出**：HUD 小字（全局）→ 分类总览提醒条（带「去重启」按钮）→ 行内角标。
- **HUD**：永远说「调试模式：…」，收起小球也在。它是开发者看截图时的第一信息源，
  日志页第三步指引顺带教会玩家截图带上它。
- **操作结果**：`applyAndRestart` 落盘成功即由 `CNRestart` 起 3 秒倒计时自动重启（Toast 告知），
  成功弹窗通常来不及出现就被重启带走——这是正常行为，不追求可见；
  失败（返回 false）必须明确弹出「没保存成功，游戏没有重启」（单按钮「知道了」）并建议重试或反馈。
  结果弹窗一律单按钮；**不做**「稍后自己重启/立即重启」双按钮——倒计时线程没有取消句柄，
  两个按钮一个拦不住一个会重复调度。
- **进入游戏被拦截**：点完重读 `isStay()`，没变就显示「还有 N 个资源包在处理，完成后才能进入游戏」。
- **重下**：`redownload()` 不弹确认，确认框归界面；文案必须点名资源包、说清已下载部分会清掉、
  说清会自动停在资源页。

## 8. 与下载浮层的分界：入口可再开，轮子不再造

P8 的逐项落实。每个重叠功能声明**唯一事实来源**（动作逻辑与状态的所有者），
悬浮窗只做两件事：调它（触发入口）、读它（只读投影）。

| 功能 | 唯一事实来源 | 悬浮窗做什么 | 悬浮窗不做什么 |
|---|---|---|---|
| 资源重下动作 | `CNManualRedownload` / 安装器（经 `CNDebugBridge.redownload` 触发） | 写第二份触发入口 + 确认框；busy/上限读 `isBusy`/`busyCount` | 不自建下载线程、不维护任务列表副本 |
| 停留状态 | 下载浮层的 stay（经 `isStay`/`setStay`） | 开关与按钮转一道手，点完**重读** `isStay()` | 不存自己的「停留」变量 |
| 下载进度 | `CNCNDownloadUI` 公开数组（fileStatus/fileProgress/…） | 浮层不在时自绘进度（同一份数据的第二个视图） | 不解析日志反推进度、不缓存进度副本 |
| 日志数据与过滤 | `CNLog`（环形缓冲、来源过滤、listener 全是静态单例） | 日志页只是 `CNLog` 的第二个渲染器 | 不开第二个缓冲、不另存过滤状态——两边过滤永远同步 |
| 日志打包分享 | `CNDebugBridge.shareLog`（flush→打包→系统分享） | 一个按钮 + null 处理 | 不自己拼 zip |
| 昼夜主题 | `CNCNDownloadUI.darkMode`（反射读色板） | 跟随 | **不提供第二个主题切换入口**——切换留在浮层右上角，两个入口=两种「当前主题」的误解 |
| 重启 | `CNRestart`（`applyAndRestart` 内部已走它） | 不直接碰 | 不写第二份重启逻辑 |
| BGM / 教程询问 / 离线导入 | 下载浮层胶囊 | **不复制入口**，悬浮窗不放这些功能 | — |

反向也成立：下载浮层已有的入口（如 LOG 胶囊）不因悬浮窗有了日志页就撤销——
前提是两处渲染同一份 `CNLog` 状态，玩家从哪边看都一样。
让位协议只撤「入口已迁移且状态唯一」的按钮（停留/重下），其余保持原位。

- **配色**：运行时反射读 `CNCNDownloadUI.COLOR_*`（清单附录写法），跟随下载浮层的昼夜切换，不自己做主题；

## 10. 边界与异常（设计侧的答案）

| 情况 | 界面表现 |
|---|---|
| native 没起来（flagTable 只回 15 行） | 分类照常显示，引擎层开关缺席；分类总览标题行显示「共 15 项（引擎层未加载）」——行数本身就是诊断信息 |
| 悬浮窗权限未授予 | 权限引导页替代主界面；「暂不开启」可退出，下次启动再引导 |
| `applyAndRestart` 返回 false | 明确提示没保存、没重启，不归咎玩家 |
| 重下任务达到上限（3） | 重下按钮置灰，顶部「任务 3/3」说明 |
| 在游戏中触发重下（下载浮层不在） | 资源修复页自绘进度（读 `CNCNDownloadUI` 公开数组），系统 Toast 辅助 |
| 玩家开了 F 类开关后来报障 | HUD 截图一眼可见（这正是 HUD 的存在理由）；分类页 F 类红标再次确认 |
| 注释表缺某个新开关 | 只显示官方说明，功能不受任何影响（P6） |
| `applyAndRestart` 阻塞 | 它在**调用线程** sleep 3 秒（接线清单线程表此处有误，清单待修订）——界面必须从后台线程调，结果 post 回 UI |

## 11. 验收清单（实现完成后逐条对）

1. 不懂技术的人不看任何文档，能完成：重下一个资源包、打包日志发出去、按名字找到指定开关。
2. 全文界面搜不到「钩子/注入/落盘/native」等禁用词（接口名与副标题除外）。
3. 每个功能页顶部都有「什么时候用这里？」或等价的场景指引。
4. 任一开关改动后：HUD、总览提醒条、行内角标三处同时出现「待重启」。
5. 勾选不点「应用并重启」就杀进程，磁盘上什么都没变。
6. F 类默认折叠；展开后每行有红色警示，打开任何注入开关前必弹「哪部分会坏」确认框。
6b. D 类不出现六个跳段勾选框，只有一个单选控件；C 类缺漏记录同理为三选一。
6c. 手工在磁盘上放两个跳段文件后打开面板：控件显示最远生效项 + 琥珀修正提示，选一项后落盘即清掉多余文件。
6d. 面板全表搜不到 `skipVersionCheck` / `skipHotUpdate` / `skipMirrorConfig`（P7）；
    过滤在接线层（`CNDebugBridge.flagTable` 出口）做，不在界面层做——出错风险归一到处。
    维护者 su 手动打开这些开关时，HUD 照常列出。
7. 杀掉 native（模拟 RegisterNatives 失败），界面不崩，行数变少且在标题可见。
8. 昼夜切换后悬浮窗与下载浮层配色一致。
9. 注释表整体删除后，界面仍完整可用（全部降级为官方说明）。
10. 分界审计（P8/§8）：`CNDebugOverlay` 全文 grep 不到 `Thread(`/`OkHttpClient`/`FileOutputStream`
    （下载与写日志都不该有自己的实现）；日志页关掉一个来源过滤后，下载浮层的 LOG 面板同步变化；
    悬浮窗里找不到 BGM / 主题切换 / 离线导入的第二个入口。
