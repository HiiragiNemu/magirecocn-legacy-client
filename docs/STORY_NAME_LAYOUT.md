# 原国服姓名布局兼容

## 范围

1.0.199 仅对普通 StoryMessage 的姓名局部位置补齐国服差异。姓名仍是原消息包裹节点的子节点；保留原引擎的安全区域、屏幕比例、左右锚点、空名与喊话处理。没有替换字体、字号、正文布局、气泡图片或任何存档与下载协议。

## 原生证据

对原国服 2.2.1 与归档基础引擎的 AArch64 副本，分别核对 StoryMessageUnit 的创建、姓名更新、正文启动和旧消息回收函数。原国服 createMessageArea 位于 0xA05AE8，归档基础引擎同函数位于 0xCE87C0。三种姓名的父节点内坐标为：

| 分支 | X | 国服 Y | 归档基础引擎 Y | 锚点 |
| --- | ---: | ---: | ---: | --- |
| 左 | -215 | 63 | 57 | (0, 0.5) |
| 中 | -55 | 63 | 57 | (0, 0.5) |
| 右 | 215 | 63 | 57 | (1, 0.5) |

这是局部坐标差异，不是固定屏幕像素差异。中间姓名按左边缘定位，不能根据姓名字数再次居中。外层适配并不属于本次修正，不能用替换整个旧函数的方式丢掉后续引擎的安全区支持。

## 限定修正与失败保守处理

在原 createMessageArea 调用期间使用线程局部作用域，借用已有字符串 TTF 创建入口记录原引擎的两个 Label。只有构造顺序、两个原字号、名字节点、三种原坐标和锚点全部符合已核实结构时，才调用原 Node 公共 API 将局部 Y 从 57 改成 63。没有修改游戏库机器码、硬编码对象内存偏移或全局 Node 位置钩子。

字号仅用于识别原节点，不作写入。已有字体调试开关关闭构造钩子、符号不可用、构造形状变化、空指针、未知位置或已经处于 63 时，全部保持原样。作用域支持嵌套并在退出时恢复；不保存超出调用期的 Label 指针。

每个进程每种位置最多记录一条不包含姓名内容的命中日志，便于安装验收确认不是只编译了未命中的代码。

## 回归与发布边界

`tools/StoryNameLayoutTest.cpp` 使用生产同一头文件，覆盖左中右、未知形状、额外构造、无效函数、已修正节点和嵌套作用域。既有手动 APK 工作流在双架构编译之前执行该测试。工作流触发方式和发布链保持不变。

本机语法/双架构构建只是前置验证，不能代替完整 APK 构建、实际安装命中、原签名兼容和升级后场景验证。应先构建校验包，在通过上述检查后才发布。版本旁注、实际 APK 和玩家更新入口必须一致；本文件不作为发布已完成的凭证。


## 2026-10-01 本机验证（不等于正式发布）

以已安装客户端为基线，只替换两个 ABI 的自有补丁库进行同签名覆盖安装验证。APK 内容逐项比对确认除两个补丁库外均未变化，四个字体文件也完全不变。

在实际第二部第二章第三话中取得左右姓名首次构造的命中日志：`slot=0` 与 `slot=2` 的局部纵坐标由 57 调整为 63；该日志只有结构、坐标和锚点全部通过守卫且调用原生位置 setter 后才会产生。原生钩子安装为 35 成功、0 失败。结束后已恢复原 APK，并保留正常热更新后的应用数据；校验包没有分发。

ARM32 版本另核对了 `createMessageArea` 的 Thumb 指令：三个分支均设置 `0x42640000`（57），横坐标分别为 -215、-55、215，标签构造字号顺序仍为 27、16；两个 ABI 的 Release 编译及主机守卫测试通过。当前模拟器支持的翻译 ABI 不含 ARM32，因此没有将 ARM32 编译通过写成 ARM32 实机验收通过。

最终分发仍须由原有构建流程产出与已签名源码对应的完整 APK，并核对签名、版本旁注、哈希和更新入口。本机校验包不代替最终发布产物。

## 正文隔离复核

姓名修正不包含正文策略迁移。当前基础引擎的正文构造保留字号27、上锚点(0,1)、TOP对齐、38行距和410最大行宽；本补丁只记录正文构造以识别随后姓名，不对正文调用位置、锚点、大小或对齐 setter。原国服固定高度及CENTER正文不在本次客户端改动范围。

发布采用现有的固定主线源码构建及同产物发布流程，不能把本机替换补丁库的校验包直接分发；完整产物必须比对上一正式版本的资源、字体、原游戏库、身份和签名后才提升在线客户端版本。脚本及剧情热更新版本不由本改动重置。


## 1.0.200：补齐姓名节点尺寸，不改正文

1.0.199 只修正局部纵坐标，遗漏了原国服姓名字号 20 与基础引擎 16 的区别。行高两者均为 25。1.0.200 在同一已核实创建作用域内，连同姓名字号一起修正；仍不触碰正文、字体文件、消息父节点、安全区域或缩放。

只有两个 Label 的构造顺序、原字号、局部坐标、锚点、渲染字号和行高全部匹配时才写入。通过公开 getTTFConfig/setTTFConfig 接口重新生成同字体、20 号的姓名标签，再恢复原有 25 行高和国服局部 Y=63。不能调用 setSystemFontSize，因为它会改变标签的字体渲染类型。

配置 ABI 已分别核对 64 位与 32 位基础引擎。修改的是公开配置值，不是 Label 对象内存偏移。原字体路径另行持有到同步 setter 及失败恢复完成，避免字体加载失败时原节点重置导致借用的路径失效。未知结构、不完整 API 或异常仍保持保守处理，不替换字体。

同源主机测试验证三个姓名槽位、字号/行高/坐标守卫、重复应用、额外构造、失败 setter、嵌套作用域以及配置除字号外逐字节不变；双架构 Release 编译通过。实际目标剧情的本机校验包已取得左、右姓名 16→20 / 57→63 命中及正文不变截图。此记录不代替最终完整 APK 的逐文件对比、签名核验和 APP 内更新验收；正式发布结果须另附实际构建和分发回执。
