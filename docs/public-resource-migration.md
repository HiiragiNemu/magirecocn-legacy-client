# 公开资源仓双入口准备

本次改动基于客户端 1.0.193 源码；不提升版本、不发布 APK、不切换现有在线配置或源仓可见性。

## 已实现的客户端范围

`CNPublicResources` 定义独立公开资源仓的固定传输锚；`CNUpdateSources` 在保留原镜像的基础上增加该公开源。客户端版本检查额外读取公开配置和 APK 旁注；热更新发现额外查询公开源；基础包选择器也保留公开兜底。EdgeOne/ESA 加速优先级、并发查询总预算、同版本同大小同哈希换线条件及冲突拒绝逻辑不变。

不修改字体路径、字体内容、剧情/UI 分流、布局、存档、规范资源 URL 或安装标记。新增入口不是新的安装身份，因此不会仅因域名迁移要求旧玩家重下资源。

## 测试边界

`python tools/test-public-resource-fallback.py` 编译真实的两个 Java 文件，在宿主 JVM 上使用受控协作者替身，验证 18 条断言：原入口保留、独立入口发现、原源模拟 404、基础包兜底、加速优先级、同身份热更换线、不同身份不混用、版本冲突拒绝和去重。它不替代 Android 真机安装与断点续传测试。现有 main 复验保持运行，不增加自动 APK 发布。

## 上线前仍须完成

- 独立资源仓全部客户端下载附件和公开配置必须完成真实同步、内容身份检查与匿名下载测试。
- 当前代码额外查询公开配置用于 APK 更新发现，不把它偷偷设为整个线路/代理控制面的权威。正式迁移时，将现有构建期配置覆盖参数指向已验证公开配置，或部署原域兼容代理；原控制面行为保持可回退。
- 在原代理部署双入口 Worker，并核实旧源返回 404 时的真实回退。只提交 Worker 文件不代表已部署。
- 已安装的 193 及以下 APK 不会因新源码提交获得新常量；旧版升级路径需保留兼容代理，或要求玩家先安装已验收新 APK。
- 字体替换及音乐符号支持单独验收后，再按现有手动流程构建 194/195；禁止只提高线上版本号。
- 所有迁移条件通过前，源仓保持现有可见性。任何私有源凭证仅由发布系统使用，不写入 APK 或公开配置。
